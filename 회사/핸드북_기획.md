## 질문 md 양식 (사용자는 작업 중 질문을 못 받는다)
```
### Q번호. 한 줄 질문 (날짜, 누가 물었나)
- 지금 정한 것: …(부서가 가장 그럴듯하게 정함)
- 다른 선택지: …
- 부작용/수치: …
```
사용자 답은 `[지금]` 이 아닌 것만 바꾼다. 답이 오면 "사용자: \"원문\"" 으로 같은 파일에 박는다.

## 해야 할 것
- 사양을 쓸 때 **사용자 원문을 인용**하고 날짜를 적는다. 해석은 "총괄 해석" 으로 구분.
- 문서끼리 어긋나면 최신 사용자 말이 이긴다. 어긋난 곳은 표로 적어 총괄에 알린다.
- 사양 뒤에 **프로그래밍 부서가 구현할 수 있는 단위**(파일·함수 이름, 예 `GridBattle.callistoPick`)까지 적는다.
- 숫자 사양엔 시뮬 근거(쿨타임·확률)가 있는 곳은 출처 표시.
- 지시 밖 밸런스 문제가 보이면 **고치지 말고 보고**.

## 과거 사고와 교훈
- **십자/X 과잉 적용(2026-11-07)**: "유도기 두 개 바꿔줘"를 12개로 확대 해석. → 애매하면 착수 전 한 줄 해석을 총괄에 올려 확인받는다. 사양 문서를 쓸 때 "대상 몇 개인가" 를 숫자로 적는다.
- 문서 줄 사이 충돌: 위쪽 옛 표와 아래쪽 새 표가 공존해 구현 부서가 옛 표를 따랐다. → 옛 표엔 "폐기, 새 표 참조" 를 남긴다.
- "3×4 칸" vs 코드 6×3 같은 숫자 불일치는 사양 쓰기 전 코드 상수를 읽어 확인(GridBattle).
- 부서원 대화가 세션 리셋으로 사라질 수 있다 → 결정은 반드시 문서에 남긴다(대화에 의존 금지).
